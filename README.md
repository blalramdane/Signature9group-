# Signature 9 Real Estate

نظام إدارة عقارات داخلي لشركة **Signature 9 Group** لإدارة العقارات المعروضة للبيع والإيجار، وتنظيم بيانات الملاك والعملاء والمتابعات والصور والمستندات، مع تجربة عربية سهلة تدعم العمل عند انقطاع الإنترنت والمزامنة عند عودته.

> **الحالة:** تأسيس وتخطيط المشروع — لم يتم إنشاء وظائف التطبيق التشغيلية بعد.

## لماذا نبني النظام؟

مصدر البيانات الحالي موزع بين محادثات واتساب والصور والرسائل، ما يجعل البحث والتعديل والمتابعة واسترجاع تفاصيل العقار عملية بطيئة وعرضة لفقدان المعلومات. الهدف هو إنشاء مصدر موحد وموثوق للبيانات، بدل الاعتماد على شيتات ومحادثات متفرقة.

## المستخدمون

- **الإدارة:** رؤية شاملة، إدارة المستخدمين والصلاحيات، متابعة الأداء والتغييرات.
- **فريق التسويق:** إضافة العقارات وتعديلها، رفع الصور، البحث، ربط العقار بمالكه وتسجيل المتابعات.
- **المستخدمون المخوّلون:** الوصول فقط إلى الوظائف والبيانات المسموح بها حسب الدور.

## النطاق الأولي (MVP)

1. **لوحة تحكم:** أعداد العقارات حسب النوع والحالة، أحدث الإضافات، والمتابعات المستحقة.
2. **العقارات:** بيع/إيجار، نوع الوحدة، الموقع، المساحة، السعر والعملة، التشطيب، التفاصيل، الحالة، الصور والمرفقات، مصدر المعلومة، وتاريخ آخر تحديث.
3. **الملاك والعملاء:** بيانات التواصل، العقارات المرتبطة، الملاحظات، سجل التواصل، والمسؤول عن المتابعة.
4. **بحث وفلاتر:** المحافظة والمنطقة، بيع/إيجار، النوع، نطاق السعر والمساحة، الحالة، والمالك.
5. **استيراد وتصدير:** Excel/CSV مع معاينة قبل الاستيراد وتقرير بالأخطاء والتكرارات.
6. **العمل دون اتصال:** واجهة PWA قابلة للتثبيت، حفظ التغييرات محليًا في طابور مزامنة، ثم مزامنتها عند عودة الاتصال مع إظهار حالة المزامنة والتعارضات.
7. **صلاحيات وسجل تدقيق:** صلاحيات حسب الدور، ومن غيّر ماذا ومتى.
8. **إدخال ذكي لاحقًا:** المساعدة في استخراج بيانات أولية من نصوص/صور واتساب أو مستندات، مع مراجعة بشرية إلزامية قبل الحفظ.

## مبدأ مهم: البيانات الصحيحة أولًا

- لا يُحفظ سجل مستخرج آليًا دون معاينة واعتماد المستخدم.
- لا تُحذف أو تُستبدل بيانات متعارضة تلقائيًا.
- كل عقار له رقم معرف ثابت، مع سجل للحالة والتعديلات.
- الصور والمستندات تحفظ كملفات مرتبطة بالسجل، لا داخل حقول نصية.
- لا تُرفع بيانات حقيقية أو أسرار وصول إلى Git.
- لا يتم نشر التطبيق أو تغيير بيانات الإنتاج أو شراء خدمات دون موافقة صريحة.

## المعمارية المقترحة

- **Backend:** Laravel API، مع اختيار إصدار متوافق مع نسخة PHP المحلية بعد فحص البيئة.
- **Frontend:** React مع TypeScript وواجهة عربية RTL متجاوبة للكمبيوتر والموبايل.
- **Database:** MySQL في البيئة المشتركة، وقاعدة محلية/تخزين محلي مناسب لسيناريو العمل دون اتصال.
- **Offline:** PWA، تخزين محلي منظم، طابور عمليات، معرّفات ثابتة، إعادة المحاولة، ومصالحة تعارضات صريحة.
- **Files:** خدمة تخزين للصور والمرفقات مع صلاحيات وصول.
- **Testing:** اختبارات للخدمات وقواعد البيانات والصلاحيات والاستيراد والمزامنة، ثم اختبارات واجهة وتدفق مستخدم.

## مراحل التنفيذ

1. تثبيت المتطلبات والحقول وقواعد البيانات والصلاحيات.
2. تجهيز هيكل المشروع وبيئة تطوير قابلة للتكرار.
3. إنشاء المستخدمين والصلاحيات وسجل التدقيق.
4. بناء إدارة العقارات والملاك والبحث والصور.
5. بناء الاستيراد والتصدير والمتابعة.
6. تنفيذ العمل دون اتصال والمزامنة ومعالجة التعارضات.
7. تجهيز بيانات تجريبية واختبارات قبول يراجعها فريق الشركة.
8. الانتقال للتشغيل المستضاف بعد موافقة منفصلة وخطة نسخ احتياطي واستعادة.

## البدء محليًا

خطوات تشغيل التطبيق الفعلية ستضاف بعد اعتماد هيكل التنفيذ وإنشاء ملفات التطبيق. لا توجد في هذه المرحلة أوامر تشغيل مكتملة للتطبيق.

## اللغة والواجهة

- العربية هي اللغة الأساسية.
- دعم RTL من أساس تصميم الواجهة.
- تصميم متجاوب للموبايل أثناء العمل الميداني.
- تكون المصطلحات والحالات قابلة للضبط دون تعديل متكرر للكود.

## تعريف النجاح

- إضافة وتعديل العقار بسرعة دون الحاجة لفتح عدة شيتات.
- العثور على العقار من خلال فلاتر واضحة.
- ربط معلومات المالك والتواصل بالعقار.
- منع التكرار وإظهار الأخطاء قبل اعتماد الاستيراد.
- معرفة حالة المزامنة والعمل المحلي بأمان.
- حماية البيانات وتوثيق التعديلات.
