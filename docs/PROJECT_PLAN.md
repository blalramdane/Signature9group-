# خطة تنفيذ Signature 9 Real Estate

## الهدف
إنشاء نظام مستقل من الصفر لإدارة العقارات المعروضة للبيع والإيجار في Signature 9 Group، وتوحيد بيانات العقارات والملاك والعملاء والمتابعات والصور، بدل تشتتها بين واتساب والشيتات.

## المستخدمون والأدوار
- **مدير النظام:** المستخدمون والصلاحيات والإعدادات وسجل التدقيق.
- **الإدارة:** جميع العقارات والتقارير والمتابعات.
- **التسويق:** إنشاء العقارات وتحديثها والصور والبحث والمتابعة.
- **مستخدم محدود:** الوصول إلى البيانات والوظائف المصرح بها فقط.

يجب تطبيق الصلاحيات على الخادم في كل طلب، وليس فقط بإخفاء عناصر الواجهة.

## تدفقات العمل
### إضافة وتعديل العقار
1. تحديد بيع أو إيجار ونوع العقار.
2. إدخال الموقع والسعر والمساحة والمواصفات المتاحة.
3. ربط المالك أو إنشاء جهة اتصال.
4. إرفاق الصور والمستندات وتسجيل مصدر البيانات.
5. مراجعة الحقول والكشف عن التكرار المحتمل.
6. حفظ العقار وإظهار معرفه وحالته.

يُسمح بحفظ مسودة ناقصة مع توضيح المطلوب قبل إتاحته للتسويق. يجب أن تكون التعديلات سهلة دون إعادة إدخال البيانات، مع تسجيل من عدّل ماذا ومتى.

### المتابعة
إنشاء متابعة مرتبطة بعقار أو مالك أو عميل، مع المسؤول والموعد ونتيجة التواصل. تعرض لوحة التحكم المتابعات المستحقة والمتأخرة.

### الاستيراد
1. رفع CSV أو Excel.
2. معاينة الأعمدة وربطها بحقول النظام.
3. التحقق من القيم والحقول المطلوبة.
4. تحديد السجلات المحتمل تكرارها للمراجعة.
5. عرض ملخص بالصفوف الصالحة والخاطئة والمحتمل تكرارها.
6. تنفيذ الاستيراد بعد اعتماد المستخدم وإظهار تقرير النتائج.

يجب ألا يستبدل الاستيراد بيانات بصمت، وأن يكون قابلاً لإعادة المحاولة بأمان.

## نطاق النسخة الأولى
- تسجيل الدخول والأدوار والصلاحيات.
- لوحة تحكم أساسية.
- إدارة العقارات وحالاتها وصورها.
- إدارة الملاك والعملاء وجهات الاتصال.
- البحث والفرز والفلاتر.
- ملاحظات وسجل متابعة.
- استيراد وتصدير CSV/Excel.
- سجل تدقيق للتغييرات المهمة.
- واجهة عربية RTL متجاوبة.

## بعد النسخة الأولى
- إكمال مزامنة Offline وحل التعارضات.
- استخراج حقول مقترحة من رسائل وصور واتساب/OCR/AI مع مراجعة بشرية إلزامية.
- إشعارات واتساب بعد التحقق من الخصوصية والتكلفة وشروط التكامل.
- تقارير تسويق متقدمة أو بوابة عامة عند اعتمادها.

## نموذج البيانات المبدئي
- `users`, `roles`, `permissions`
- `properties`, `property_media`
- `contacts`, `property_contact`
- `follow_ups`, `activity_logs`
- `import_jobs`, `import_rows`
- `sync_operations` عند تنفيذ المزامنة
- `lookup_values` للأنواع والحالات والمناطق

تُثبَّت العلاقات والحقول والقيود قبل اعتماد أول migration. جهة الاتصال يجب أن تكون سجلاً مستقلاً يمكن ربطه بأكثر من عقار عند الحاجة.

## مراحل التنفيذ ومعايير القبول
### A — تثبيت الأساس
مراجعة إصدارات البيئة وتثبيت الحقول والحالات والأدوار. القبول: يستطيع مطور جديد فهم نطاق المشروع والقرارات.

### B — أساس التطبيق
تجهيز API والواجهة والبيئة المحلية وملفات مثال للإعدادات وفحوص CI. القبول: نجاح التثبيت والبناء والاختبارات الأولية في بيئة موثقة.

### C — العقارات وجهات الاتصال
CRUD للعقارات والملاك والعملاء ورفع الصور والبحث والصلاحيات. القبول: تدفق الإضافة والتعديل والبحث يعمل باختبارات مناسبة.

### D — المتابعة والاستيراد
تسجيل التواصل والاستيراد بالمعاينة وتقرير الأخطاء والتصدير المقيد بالصلاحيات. القبول: بيانات تجريبية سليمة وخاطئة ومكررة لا تفسد السجلات.

### E — Offline والمزامنة
طابور محلي دائم، عمليات idempotent، مؤشرات حالة المزامنة، وآلية صريحة للتعارضات. القبول: نجاح اختبارات انقطاع الاتصال والتكرار والتعديل المتزامن دون فقد صامت.

### F — الإدخال الذكي
استخراج أولي من النصوص والصور مع عرض المصدر والثقة، ثم اعتماد المستخدم. القبول: لا تُحفظ سجلات جاهزة للنشر من نتائج آلية غير مراجعة.

### G — اختبار التشغيل
تجربة ببيانات وهمية، اختبار قبول مع التسويق والإدارة، مراجعة الأمن، وتجربة النسخ الاحتياطي والاستعادة. النشر الفعلي يحتاج موافقة صريحة منفصلة.

## خطة الاختبار
- اختبارات الوحدات والتحقق والخدمات.
- اختبارات API وقاعدة البيانات والصلاحيات.
- اختبارات الاستيراد: أعمدة ناقصة، قيم غير صحيحة، تكرارات، وإعادة المحاولة.
- اختبارات رفع الملفات غير المسموحة والأحجام الزائدة.
- اختبارات Offline: انقطاع، تكرار، تأخر، تعارض، وتسجيل خروج.
- اختبار النسخ الاحتياطي والاستعادة قبل التشغيل الحقيقي.

## المخاطر والضوابط
| الخطر | الضابط |
|---|---|
| تكرار العقارات | كشف التشابه ومراجعة بشرية، دون دمج تلقائي |
| فقدان تعديل Offline | طابور محلي دائم وعرض حالة العملية |
| تعارض المستخدمين | قواعد واضحة وسجل قرار |
| حساسية بيانات الاتصال | أقل صلاحيات، نقل مشفر، ونسخ احتياطي محمي |
| ملفات ضارة | فحص النوع والحجم والامتداد |
| استيراد خاطئ | معاينة وتقرير وإعادة آمنة |
| أخطاء AI | مراجعة بشرية وعرض المصدر |

## ضوابط المشروع
- لا تُرفع بيانات العملاء الحقيقية أو الأسرار إلى Git.
- لا تُغيّر بيانات الإنتاج ولا تنشر النظام دون موافقة صريحة.
- لا تُفعّل خدمات مدفوعة أو تكاملات خارجية قبل مراجعة التكلفة والشروط.
- لا تُعتبر أي ميزة مكتملة دون اختبار موثق.
- حدّث هذه الخطة عند اكتمال كل مرحلة، وسجّل القرارات غير المحسومة في `DECISIONS.md`.
